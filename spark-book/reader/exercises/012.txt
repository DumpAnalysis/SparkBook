Exercise 12  Establish a CPU control

Question
How much does execution placement change latency for the same answer?

Before you start
Exercise 5 (start the baseline server) · Exercise 8 (measure repeated local requests)
Python standard library; native runtime for inference. Reserve at least 20 GB free disk before Exercise 4 (planning allowance, not a measured peak).

Recorded step time
2 min 33 s for Q4 on CPU — benchmark (record 012.02).

Check for success
Verify CPU versus GPU placement in the two logs. Compare medians only after checking that the prompt, token counts and response task match.

Predict before running
Estimate the CPU/GPU latency ratio before reading the measured medians.

Run in your lab
Begin with the entry procedure below, then complete the variations and acceptance checks in the chapter.

: "${LAB_RUN:?Run source reader/new_run.sh first}"

bash serve.sh stop
env LLAMA_ARG_LOG_VERBOSITY=5 bash serve.sh start 4096 1 0 cpu q4_k_m
python spark_lab.py bench prompt.txt --runs 5 --workers 1 --tokens 128 --out "$LAB_RUN/cpu-benchmark.json"
python spark_lab.py summarize "$LAB_RUN/cpu-benchmark.json"
bash serve.sh stop
env LLAMA_ARG_LOG_VERBOSITY=5 bash serve.sh start 4096 1 99 gpu q4_k_m
python spark_lab.py bench prompt.txt --runs 5 --workers 1 --tokens 128 --out "$LAB_RUN/gpu-benchmark.json"
python spark_lab.py summarize "$LAB_RUN/gpu-benchmark.json"

Interpret the result
This deliberate CPU control remains useful evidence. Compare equivalent work and disclose the changed backend.

If the check fails
Check the first failed boundary: file, loader, service health, request, then answer.

Finish
Keep both five-request summaries and both native placement logs. Stop the GPU owner when leaving the route.

Handoff
