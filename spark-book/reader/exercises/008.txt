Exercise 8  Measure repeated local requests

Question
How repeatable is a response after the model has warmed up?

Before you start
Exercise 5 (start the baseline server) · Exercise 6 (submit the complete prompt) · Exercise 7 (understand the arithmetic first)
The active baseline server, the R17 prompt used in Exercise 6 and a new benchmark.json path.

Recorded step time
16.4 s for Bench (record 008.01).

Check for success
Separate the warm-up from the five measured requests. Compare token counts, complete answers and cached input before comparing elapsed times.

Run in your lab
Begin with the entry procedure below, then complete the variations and acceptance checks in the chapter.

: "${LAB_RUN:?Run source reader/new_run.sh first}"

python spark_lab.py bench prompt.txt --runs 5 --workers 1 --tokens 128 --out "$LAB_RUN/benchmark.json"

Inspect
Read every response and finish reason, then compare repetition count, output lengths and latency/rate summaries.

Interpret the result
A fast failure is not a fast answer. Compare equivalent work and separate first-use effects from repeated requests.

If the check fails
Check the first failed boundary: file, loader, service health, request, then answer.

Finish
Keep individual request records as well as the aggregate. Leave the server running only for the next planned measurement.

Handoff
Keep $LAB_RUN/benchmark.json. Use the separate warm-up and five measured requests for your conclusion in Exercise 23.

Recorded result  The five measured requests each returned 127 completion tokens. The warm-up had zero cached prompt tokens and the repeats had 113.
Scope  The five measured repetitions used the same prompt and a warm server.
