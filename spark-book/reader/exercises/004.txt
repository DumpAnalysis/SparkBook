Exercise 4  Download and fingerprint

Question
Could someone identify the exact runtime and weights used in this lab?

Technology background

Model downloads, Git revisions and GGUF

A model repository holds weights, configuration and a description called a model card. A revision identifies a particular state of that repository. A SHA-256 digest is a fingerprint of a file’s bytes. Compare it with the expected digest before loading. Two similarly named files may contain different weights.

The early exercises use Qwen models. Its GGUF files contain tensors and metadata in a format the llama.cpp runtime can read. A large model can be split into numbered shards. Keep the runtime identity, model revision and complete shard list together so another reader can reconstruct the same load.

Git repositories, snapshots and saved run directories

Git records versions of a project. A commit identifies one saved version. GitHub hosts the companion repository. A clone gives you its files and Git history. A release ZIP gives you a snapshot you can use without learning Git commands. The companion supplies the small programs and teaching inputs. Large downloaded model weights have their own identities.

Keep the staging copy apart from your working lab. A fresh run directory holds the command, results and logs from one attempt. When comparing two trials, keep both directories and note the software revision used for each.

Check for success
Match both runtime archives and both Q4 shards to the saved SHA-256 values. The Q4 shard sizes and the pinned revision must also agree.

Run in your lab
The normal setup verifies files as it acquires or reuses them. To recheck an existing cache without a download or extraction, run python setup_wsl.py --verify-only instead.

Inspect
Check runs/linux-manifest-q4_k_m.json against reader/native-asset-pins.json. Model hashes identify the files used on the example laptop.

Interpret the result
Successful acquisition establishes which files are present; Exercise 5 tests whether this runtime can load them.

If the check fails
A size or SHA-256 mismatch names the file. Retain that error and move the affected cached file aside before retrying acquisition.

Finish
Keep the model shards and receipts at their configured paths for Exercise 5.

Handoff
Keep the two verified archives, both model shards and runs/linux-manifest-q4_k_m.json. Exercise 5 loads the first shard and discovers its partner.
