81  Images audio and multimodal evidence

A media model introduces more observable boundaries. An image has an orientation, color representation and spatial resolution before it becomes a tensor. Audio has a sample rate, channel layout and duration before it becomes features or codec tokens. We retain these transformations because a plausible output can conceal a wrong input. The same diagnostic method now follows pixels and samples through preprocessing, model execution, decoding and the final file.

The new laboratory uses five pinned publisher checkpoints: Qwen2.5-VL-3B-Instruct for image questions, Stable Diffusion XL base 1.0 for images, MusicGen small for music, MMS English VITS for speech synthesis, and Whisper tiny for speech recognition. These are manageable teaching baselines, not a ranking of current models. media/models.lock.json records full repository revisions and selected files. The model families have different licenses: Qwen research terms, OpenRAIL++ for SDXL, CC-BY-NC 4.0 for the selected Meta weights, and Apache-2.0 for Whisper tiny. Keep the exact model terms with any deployment decision. [147, 152, 155, 157]

83  Diffusion models through a small executable experiment

Diffusion training starts with a known clean sample, adds noise according to a schedule and learns information needed to reverse that corruption. In the epsilon-prediction formulation used here, a network predicts the added Gaussian noise. Sampling begins with noise and repeatedly applies the learned reverse update. This is an iterative numerical process; a wrong timestep, scaling factor or prediction convention can produce finite but meaningless output. [150]

We first use two-dimensional points instead of images. The small distribution makes every tensor inspectable and allows CPU training with no publisher download. Eight noisy clusters lie around a ring. A 4,610-parameter network receives the noisy coordinates and two timestep features. This is an unconditional teaching model; it has no text encoder, VAE, image decoder or language understanding.

Exercise 180  Verify forward corruption and an oracle reconstruction

# Core operations from media/diffusion_control.py

beta = torch.linspace(.0001, .08, 100)

alpha = 1 - beta

abar = torch.cumprod(alpha, 0)

xt = abar[t, None].sqrt() * x

xt = xt + (1 - abar[t, None]).sqrt() * noise

x0 = (xt - (1 - abar[t, None]).sqrt() * noise)

x0 = x0 / abar[t, None].sqrt()

Read the schedule in the source, then run the complete experiment in Exercise 181. The oracle reconstruction uses the exact noise that created the noisy point. It checks the arithmetic independently of learning. Replacing that noise by its negative is a deliberate fault. The executed control obtained a maximum correct reconstruction error below one millionth, while the wrong-noise reconstruction had a mean squared error above 32. These quantities compare different reductions and should not be divided into a purported speed or quality improvement.

The schedule contains positive beta values below one, with monotonically decreasing cumulative alpha. Do not replace epsilon prediction with clean-sample or velocity prediction without changing the reverse formula and scheduler convention. A model file and a scheduler configuration form a compatibility pair. The numerical guard checks finite values but cannot establish that this pair has the intended semantics.

Exercise 182  Inspect reverse sampling and distribution coverage


Figure 83.1  Executed CPU diffusion control. Held-out points and 512 generated samples share the same axes. The plot exposes coverage and dispersion; it does not measure image quality.

The reverse loop visits all 100 schedule indices in descending order. It computes the mean from the predicted noise and adds posterior noise except at the final step. Inspect the posterior variance expression in the source. A negative variance or a nonfinite point is a numerical failure; a missing cluster is a distributional failure. The two need different evidence.

Load reference.npy and samples.npy, compare radius distributions and count occupancy near each of the eight centers. Keep outliers visible instead of rescaling the plot until both clouds appear similar. The retained samples recover a ring but blur the eight distinct clusters. Lower noise error therefore does not establish the correct mode structure. A few attractive samples cannot establish coverage. Repeat training with another explicitly recorded seed only after preserving this baseline. A different point cloud is expected even when the training method remains correct.

Exercise 183  Map the teaching loop to an image pipeline

Make a five-row investigation record: input conditioning, initial noise, denoising network, scheduler update and output decoding. For each row name its input tensor, dtype, shape, device and retained evidence. In SDXL, text encoders condition a denoising network that operates in a latent representation; the VAE converts the resulting latent to pixels. The point experiment isolates schedule and learning behavior without those additional components. [148, 150]

A useful failure injection changes one convention at a time. Negate the known noise for the oracle control, reverse the schedule order in a copied experiment, or change the timestep supplied to the predictor. Preserve the original script and give the variant a new name. Compare finite-value checks, reconstruction error and distribution coverage. Do not inject all three faults together: their interaction would weaken the evidence for the first failed boundary.

The lesson transfers beyond diffusion. Flow-based generative models also use iterative transformations, but their prediction targets and integration rules differ. Treat a different model family as a new numerical contract. The existence of a generate method does not make scheduler settings interchangeable.

85  Music generation and audio token diagnostics

Music generation is not necessarily diffusion. MusicGen predicts discrete audio-code sequences conditioned on text, then an audio codec decodes them into a waveform. This gives us separate representation and timing boundaries: text encoder, autoregressive token generation, codec decoding and WAV export. We use the small mono checkpoint to keep the first request bounded. A larger decoder or stereo variant is a separate qualification. [151, 153]

Exercise 189  Inspect waveform and spectral activity

python media/capture.py --out runs/media/music-analysis-log -- \

  python media/analyze.py --audio runs/media/music-short/output.wav \

  --out runs/media/music-analysis

analyze.py retains decoded source properties and plots a mono waveform and short-time Fourier transform. The vertical spectral axis is frequency, not a learned embedding coordinate. The color scale is 20 log10 of STFT coefficient magnitude relative to one. With the default spectrum scaling, an interior bin of a bin-centered real sinusoid with peak amplitude one is about −6.02 dB, because its positive- and negative-frequency coefficients each have magnitude one half. This is not a calibrated sound-pressure or loudness scale. [168] Silent gaps, sudden cuts and broadband bursts can now be compared with audible events. The STFT window trades time localization against frequency detail; changing it is a new analysis setting, not a change in the underlying audio.

The writer refuses amplitudes outside the normalized range instead of silently clipping them into a PCM file. If that guard fires, retain waveform.npy and inspect its peak, finite values and channel layout. Normalize or limit only in a separately recorded postprocessing step. The clipping fraction alone is not a loudness measure; RMS also depends on the signal and channel policy. For a delivery standard, add the required loudness measurement and document that separate tool.

Exercise 197  Score recognition without hiding normalization choices


Word error rate is edit distance divided by the number of reference words; insertions can make it exceed one. The companion uses Unicode word tokens, case folding and punctuation removal. It does not silently expand numerals or units. An empty reference has an undefined rate in this implementation, with the insertion count retained separately. This avoids reporting zero error for hallucinated words over silence. [158]

Exercise 198  Recognize the absence of acoustic evidence


The actual CPU run returned the word you from a two-second all-zero waveform. The file is not a mislabeled speech recording: its retained peak and RMS are zero. This is a useful counterexample to the rule that a nonempty transcript proves speech was present. It also shows why an HTTP success code cannot serve as a transcription-quality judgment.

Repeat the silent clip on the laptop, then compare with quiet room noise and a spoken word. The exact hypothesis may change across environments. Record false positives rather than demanding the same word. A digital-silence check can reject the all-zero case before inference; a real service needs a qualified voice-activity detector, segmentation policy and false-positive evaluation. An energy threshold alone can reject quiet speech or accept non-speech noise.

Do not convert an uncertain transcript directly into a privileged action. The voice wrapper in Chapter 88 rejects digital silence, accepts no model-generated tool calls and retains every text boundary. That wrapper is still not a validated detector of speech in room noise. Confidence-like decoder values and language probabilities require calibration before they can justify an automatic acceptance policy.

88  Adapting and serving multimodal pipelines

A multimodal application joins models with different resource demands and evidence types. Recognition can produce text for a language model, which can produce text for synthesis. An image may be generated and then described by a vision-language model. Each connection needs an explicit representation contract and a quality check. We first exercise adaptation, then join qualified components while retaining their boundaries.

Exercise 203  Share GPU ownership and deploy bounded media requests


This executed CPU simulation admits short recognition, image and speech requests, rejects a music request over the token budget, and observes at most one active owner. It is an admission and ownership control, not a measurement of GPU scheduling or application throughput. To build a service, put actual model execution behind the bounded owner and add cancellation, deadlines and output retention from Chapters 71–72.

A media request needs modality-specific limits: decoded image pixels, generated dimensions, audio duration, sample rate, output tokens and synthesis characters. Also bound compressed upload bytes and queue length before decoding untrusted files. A small compressed image can expand into a large tensor. Expose readiness only after the model is loaded and a representative request succeeds; liveness should not trigger a restart merely because a long generation is busy.

For Docker, reuse the WSL2 GPU runtime qualification, non-root ownership, writable caches and read-only model mounts from Chapter 73. Build a new media image containing the qualified environment and these scripts; do not assume the earlier text-server image supplies its dependencies. For Kubernetes, retain one GPU owner, a persistent model volume, explicit /tmp and output capacity, and the startup timeout needed for loading. K3s owns a separate image store. Multiple replicas can duplicate all model weights even when requests are small.

vLLM support is model-and-version specific: qualify the selected vision-language architecture, its processor and image limits before using its serving API. NVIDIA Triton can host separate preprocessing, model and postprocessing stages, but dynamic batching must respect image shapes, audio lengths and decoder behavior. An ONNX or TensorRT export of one component is not automatically an export of the entire diffusion or speech pipeline. Keep the full Python baseline as the comparison oracle before accelerating individual components.
