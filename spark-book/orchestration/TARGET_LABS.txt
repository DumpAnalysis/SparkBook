# 92  LangChain agents and local model adapters

The earlier agent laboratory exposes the controller directly. This chapter repeats that separation with LangChain: the framework owns a model/tool loop; a model proposes calls; application code decides which operations exist. LangChain's create_agent supplies that loop using LangGraph. A framework does not supply model weights, GPU memory or permission to execute arbitrary tools. The files in orchestration/ add to the earlier agent examples rather than replacing their evidence. [205]

The example still has 64 GB unified memory and about 30 GB reported for the GPU. Run the orchestration process on the CPU in WSL2 and reuse one qualified local inference server as the model owner. Four agents need not mean four copies of the weights. Concurrent requests can still increase KV-cache use, queue time and host memory. Apply the admission and batching studies in Chapter 71 before increasing concurrency.

The five chapters that follow use LangChain for the agent loop, LangGraph for explicit state and recovery, LangSmith for application traces and evaluation, PydanticAI for typed outputs, and Jev for probability-bearing decisions. LangSmith traces and Jev API responses do not measure local CUDA kernels. Their optional hosted-service procedures run clients in WSL2; service-side execution is remote. The core controls require no service account.

Evidence boundary. Preparation used Python 3.12.14 on Linux x86-64 without a GPU. The actual installed frameworks executed scripted model controls, persistent graph state, local traces, offline evaluation and loopback HTTP adapters. No new learned model ran. No ARM64, WSL2 GPU, LangSmith service or hosted Jev execution is claimed. Every synthetic input, response and score is labelled. Fifteen full CPU command captures and the preparation failures are retained in orchestration/evidence/.

# 93  LangGraph state, interrupts and recovery

An agent's next action is only part of its state. A diagnostic workflow also has an incident identity, collected evidence, pending review and a terminal result. LangGraph makes those transitions explicit. Its checkpoint is application state, not a GPU-memory snapshot, optimizer checkpoint or saved model context. The database can survive a process exit while the inference server and its KV cache have a separate lifetime. [207]

The supplied graph has a review node followed by a finish node. review calls interrupt with a proposed read-only investigation. The finish node either records a denial, records a simulated approval, or invokes the bounded LangChain loop. SqliteSaver stores checkpoints in the WSL Linux filesystem. Each invocation identifies a thread. Thread identity is a storage lookup key; it is not an authentication boundary. [208, 209]

## Exercise 223  Resume after the Python process exits

Goal: prove that continuation comes from durable storage. graph_control.py launches graph_lab.py twice using separate Python processes. The first exits after the interrupt. The second opens the same SQLite database and resumes the same thread with an explicit Boolean approval. This is an executed recovery control; it does not simulate a GPU or call a learned model.


TARGET manual session. These commands run as separate processes even in one terminal:

```

python orchestration/graph_lab.py start \

  --db runs/graph-01/checkpoints.sqlite \

  --thread incident-01 --case SIMULATED-001 \

  --out runs/graph-01/start.json

python orchestration/graph_lab.py status \

  --db runs/graph-01/checkpoints.sqlite \

  --thread incident-01 --out runs/graph-01/status.json

python orchestration/graph_lab.py resume \

  --db runs/graph-01/checkpoints.sqlite \

  --thread incident-01 --approve yes \

  --out runs/graph-01/resume.json

```

The pause exposes next=[review]. After resumption, the finished state has no pending node. Keep the database and its complete source/version identities together. Copy databases only after the owning processes have stopped or through an appropriate consistent backup mechanism. The exercise demonstrates sequential process restart; it does not qualify concurrent writers, migrations, power-loss recovery or a distributed database.

## Exercise 224  Reject wrong-thread and duplicate continuation

Goal: prevent a resume request from being mistaken for a new incident or replayed after completion. The wrapper checks for an existing pending checkpoint. A new thread has no such checkpoint; a completed thread has no next node. The control rejects both. It also refuses start when that thread already has saved state.


Run the faults mode only against the completed thread from Exercise 223, or use graph_control.py faults with a fresh output directory to construct the prerequisite itself. These checks are application guards, not a general exactly-once guarantee. Two concurrent workers could race between the check and resume. For shared service deployment, add authenticated incident ownership and a transactional coordination design, then fault-test it.

The interrupted node starts again when resumed. Put no irreversible effect before interrupt. If a later node sends a request, writes externally or charges a service, a failure between that effect and checkpoint commitment can cause repetition. Use a durable operation identity and verify the receiver's deduplication behavior. A model response or database checkpoint alone does not grant exactly-once semantics. [208]

# 94  LangSmith traces and evaluation

LangSmith describes application execution as runs with parent/child relationships, inputs, outputs, errors and timing. That view answers which tool failed or which model attempt was retried. Prometheus answers how rates and resource observations change over time; CUDA tools answer what executed on the device. These views complement each other. A LangSmith model span measures a client-side operation, not CUDA kernel time. [210]

The core exercises use the installed LangSmith SDK without a LangSmith account or remote trace submission. A local JSON trace is an artifact, not a self-hosted LangSmith server or a rendered LangSmith dashboard. Self-hosted LangSmith is a separately licensed Enterprise deployment with its own infrastructure requirements; installing the Python SDK or LangGraph does not install that service. [213]

# 96  Jev decision models and calibrated routing

Jev is TypeSafe's decision-model family. Its documented interface accepts state plus named, typed questions and returns structured answers. Choice selects among named alternatives; Score uses an ordered rubric; Noul returns a probability of yes. The laboratory uses the official TypeSafe endpoint and the versioned identifier jev-1.14.0 listed on 28 October 2026. The official API's response model field identifies the model used. Third-party gateways may use different identifiers and limits. [218, 219]

This chapter does not present Jev as downloadable local weights. The documented API route runs inference remotely. All client commands and offline evaluation controls run in WSL2, but neither the 64 GB host memory nor the approximately 30 GB GPU report determines that service's model capacity. No local Jev checkpoint or CUDA execution recipe is supplied. Use the earlier local BERT and embedding classifiers when the requirement is to keep both data and inference on the laptop.

A structured answer can be wrong. A restricted answer set prevents certain representation errors; it does not guarantee a correct diagnosis, sound policy or resistance to misleading evidence. Separate output validity, probability calibration and downstream action quality. The examples route to diagnostic categories and never execute a command selected by the model.

## Exercise 233  Measure calibration and risk versus coverage

Goal: prove the evaluator arithmetic before assessing a model. Six invented binary outcomes and predicted probabilities deliberately include confident mistakes. Binary Brier score is the mean of (p-y) squared. Coverage is the accepted fraction of cases; selective risk is the error fraction among those accepted. The control accepts a binary decision when max(p,1-p) reaches the threshold. It does not threshold Jev's transformed Choice confidence.


The stricter threshold accepts fewer cases but has higher error in this tiny counterexample. Thus a confidence threshold cannot be justified by intuition alone. These six rows illustrate arithmetic and are far too small to estimate model calibration. For a real study, separate threshold tuning from held-out testing, keep case identities and labels fixed, record class balance, and report uncertainty with the sample counts. An accepted set with no cases has undefined risk; it must not be reported as zero error.

```

python catalogs/capture.py --out runs/jev-calibration -- \

  python orchestration/jev_lab.py calibration \

  --out runs/jev-calibration/result.json

```

Extend the retained table with a reliability diagram: group predicted probabilities into bins, plot each bin's mean prediction against its observed positive fraction, and show bin counts. For a multiclass Choice, document whether you use a multiclass Brier score or a top-label calibration measure. A changed class set, rubric wording, dataset distribution or model version can invalidate a previous threshold. Do not compare transformed confidence values across different question types as if they were the same probability.

Integrate a validated decision into LangGraph as a routing node: invalid response or uncertain result leads to review; an accepted category selects a read-only evidence investigation. Keep the routing policy in application code. Record request duration, answer distribution, model identity and final route in a trace. Remote service latency is not evidence of local GPU occupancy or of Jev's server kernel time.
